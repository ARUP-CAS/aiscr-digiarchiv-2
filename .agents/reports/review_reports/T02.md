# T02 — Internal and external dependency graph

**Date:** 2026-03-08
**Affected files:**
- `web/pom.xml`
- `ThumbnailsGenerator/pom.xml`
- `web/src/main/ng/package.json`
- `web/src/main/java/cz/inovatika/arup/digiarchiv/web4/` (all packages)

---

## 1. Summary of findings

The repository contains two independent Maven modules (`web/` and `ThumbnailsGenerator/`) with no common parent POM. The main Java application targets **Java 17 + Jakarta EE 11**, ThumbnailsGenerator targets **Java 1.8** — an inconsistent runtime. The frontend is Angular 21 with TypeScript ~5.9.3.

The critical finding is **Saxon 8.7** (an XSLT processor from 2006) — used via the Maven dependency `net.sf.saxon:saxon:8.7`. The current version is Saxon-HE 12.x. This dependency is critically outdated (~18 years) and lacks security patches. Although AGENTS.md states an XSLT 2.0/3.0 processor, Saxon 8.7 has only partial XSLT 2.0 support and no XSLT 3.0 support at all.

Further problems are an EOL dependency (Apache XML-RPC) and the `javax.mail` namespace incompatibility in a Jakarta EE 11 project.

Architecturally, two **god classes** over 1000 lines are apparent (`SolrSearcher`, `FedoraHarvester`), plus tight coupling to the external AMCR Fedora API.

## 2. Identified problems

### 2.1 Maven dependencies (`web/pom.xml`)

| Dependency | Version | Problem |
|-----------|-------|---------|
| `net.sf.saxon:saxon` | **8.7** (2006) | Critically outdated — 18 years of patches missing; Saxon-HE 12.x is current |
| `org.apache.xmlrpc:xmlrpc-client` | 3.1.3 | EOL since 2016 — no security updates |
| `javax.mail:mail` | 1.4.7 | Old `javax.mail` namespace in a Jakarta EE 11 project (expects `jakarta.mail`) |
| `org.apache.httpcomponents:httpclient` | 4.5.14 | HttpClient 4.x — the project otherwise uses `java.net.http` (JDK 11+); duplication |

### 2.2 ThumbnailsGenerator (`ThumbnailsGenerator/pom.xml`)

| Problem | Detail |
|---------|--------|
| Java version | Compiles for Java 1.8, main app on Java 17 |
| Version range | `thumbnailator:[0.4,0.5)` — non-deterministic build |
| Missing parent POM | Shared versions (`pdfbox`, `commons-io`, `org.json`, `solr-solrj`) must be synchronized manually |

### 2.3 npm dependencies (`package.json`)

| Dependency | Problem |
|-----------|---------|
| `@ngu/carousel:^20.0.1` | Version for Angular 20, the application is Angular 21 — incompatibility risk |
| `axios:^1.11.0` | Redundant — duplicates Angular HttpClient; increases bundle size |
| `moment:^2.30.1` | Maintenance mode since 2020; migration recommended |
| `leaflet.locationfilter:^0.1.0` | Version 0.x, probably an unmaintained project |

### 2.4 Architectural problems — internal Java dependencies

| Class | Lines | Problem |
|-------|-------|---------|
| `SolrSearcher` | 1,048 | God class — query building, access control, facets, thesaurus all in one class |
| `FedoraHarvester` | 1,024 | God class — Fedora communication, transformations, bulk indexing, error handling |
| `SearchServlet` | 634 | Central servlet with 17+ Actions; tight coupling to Solr and Fedora |
| `SearchUtils` | 344 | Massive switch statements for 12+ entity types; should be factory/config driven |
| `Options` | 276 | Singleton — global mutable state; potential concurrency problems |

**Duplicated path validation logic:** Both `ApiServlet` and `InitServlet` contain their own implementation of safe path normalization — it should be extracted into a shared utility.

## 3. Improvement proposals

### High priority

1. **Upgrade Saxon 8.7 → Saxon-HE 12.x**
   - Saxon-HE is open source, backward compatible for XSLT 2.0
   - Adds full XSLT 3.0 support (matches AGENTS.md)
   - Change in `pom.xml`: `net.sf.saxon:Saxon-HE:12.5`

2. **Refactor the god classes**
   - `SolrSearcher`: extract access level logic into `AccessLevelService`, thesaurus into `ThesaurusService`
   - `FedoraHarvester`: extract record-type handlers into Strategy implementations

3. **Add Java tests** (recorded in T01, repeated here for priority)
   - JUnit 5 for `SearchUtils`, `SolrSearcher`, `FedoraUtils`, `IndexUtils`

### Medium priority

4. **Replace `javax.mail` with `jakarta.mail`**
   - Add `jakarta.mail:jakarta.mail-api` + the Angus Mail implementation
   - Replace `commons-email` with Jakarta Mail directly or Eclipse Angus

5. **Remove Apache XML-RPC (EOL)**
   - Locate the usages of `xmlrpc-client` in the code; replace with `java.net.http`

6. **Add a root parent POM**
   - Centralize versions of shared dependencies (pdfbox, commons-io, org.json, solr-solrj)
   - Eliminate manual version synchronization between `web/` and `ThumbnailsGenerator/`

7. **Upgrade ThumbnailsGenerator to Java 17**

8. **Unify HTTP clients in `web/`**
   - Remove `org.apache.httpcomponents:httpclient` and migrate everything to `java.net.http`

### Low priority

9. **Remove/replace axios** with Angular HttpClient
10. **Migrate Moment.js** → date-fns or the native Angular DatePipe
11. **Pin the thumbnailator version** (instead of the range `[0.4,0.5)`)
12. **Extract path normalization** from ApiServlet and InitServlet into a shared utility
